# 角色

角色是**职责与边界**，不是固定编制。按任务启用，简单任务只用一到两个；不要求凑齐下表全部。

> 下表的**角色分离与独立审查要求，只在真正以团队方式工作时适用**。若任务简单到由单一执行者
> 直接完成，它就不属于团队工作：不分配角色、不要求分离，也**不存在**独立审查这一环。
> 直接执行时不要引用本表来暗示已经做过角色分离或独立验收。

| 角色 | 职责 | 写权限 | 不该做的事 |
| --- | --- | --- | --- |
| 协调者 Coordinator | 界定目标与验收、拆分任务、决定启用哪些角色、分派与改派、维护依赖与证据、做最终验收 | 计划与记录；原则上不直接改产品代码 | 不替实现者写代码来“救活”失败任务；不跳过独立审查 |
| 顾问 Advisor | 只在存在真实的需求/产品/验收歧义时给出判断与取舍建议 | 只读 | 不做常规实现；不对无歧义问题发表“意见” |
| 探索者 Explorer | 只读调查：定位相关文件、数据流、约束、风险与最小改动面 | 只读 | 不改任何文件；不把猜测写成结论 |
| 执行者 / 编码者 Coder | 在给定写作用域内实现或修复，自证基本可用性 | 仅自己的 allowlist | 不扩大写作用域；不改他人负责的文件 |
| 测试者 Tester | 独立验证：验收标准、回归、边界与失败路径 | 只读产品代码；如需改测试/夹具，走独立工作包与 allowlist | 不改产品代码；不审自己写的东西 |
| 审查者 Reviewer | 独立审查改动与规则符合性，给出可复现的问题与结论 | 只读 | 不顺手修好；不与实现者同一视角自证 |
| 记录者 Recorder | 维护进度、决策、证据索引，使结论可追溯 | 只写记录类产物 | 不修改被记录的事实；不做实现 |

## 只读 / 可写的实际含义

- **只读**：可以读取、搜索、运行不改变仓库状态的命令；不得创建、修改或删除受版本控制的文件，
  也不得通过生成临时产物绕过边界（临时目录内的中间产物除外，用完即清）。
- **可写**：仅限任务声明的 allowlist。需要写到 allowlist 之外时，先停下来向协调者说明，
  由协调者扩展合同或改派，而不是自行扩大范围。

## 能力匹配

- 角色与**执行后端**解耦：同一角色可以由原生子代理、远程执行框架或人工承担。
- 若某角色所需能力当前执行者不具备，必须改派给具备该能力的执行者或专用工具；不得声称完成。
- **两种能力不要混为一谈**：
  - **图像生成 / 图像编辑**需要真正的**图像生成或编辑工具**（产出像素结果）；
  - **视觉理解**——识图、OCR、截图分析、GUI 视觉判断与视觉验收——需要真正的**视觉能力**
    （能看并判断既有图像）。
  有其中之一不等于有另一个。纯文本执行者既不能生成图像，也不能“看图”，更不得用文字描述
  假装视觉结论；缺哪种能力就如实说明缺哪种。

## 独立性

- 独立性来自**由不同执行者完成**：审查者不得审查自己实现的内容，测试者不得验证自己写的代码。
- 独立性与**是否并行无关**：不同执行者串行工作同样可以保持独立审查——“顺序执行”本身不是
  独立性不足的理由。
- 只有当**确实没有第二个执行者**时，才不存在独立审查。这时如实说明这是**单执行者自检**，
  不得称其为独立审查，也不得把同一执行者扮演的不同角色描述成相互独立验收。
